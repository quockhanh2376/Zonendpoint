# Zonendpoint v1.0.0 product scope

This scope supersedes earlier UI language and theme requirements that conflict with v1.0.0.

## Product surface

- All text written and controlled by Zonendpoint is English: screens, menu items, buttons, tooltips, accessibility labels, statuses, validation, errors, notifications, and installer content.
- Native Windows dialogs may use the operating system's display language. User-provided paths and file names are data, not translated product copy.
- The v1.0.0 interface starts in Light theme on first launch and provides an accessible Light/Dark toggle that persists the user's choice across app restarts.
- English/Vietnamese language selection remains out of scope; do not show a language selector or translated placeholder.
- Do not add an i18n library or theme framework for v1.0.0. Reuse the app's CSS tokens and local storage.
- Real-time protection remains off in this MVP; UI copy must not imply that protection is active.
- Initial deployment target is an internal company pilot (Zon confirmed2026-11-07). This does not imply approval for public feeds/APIs, uploads, licensing implementation or a signed/public release.

## Backlog after v1.0.0

- English/Vietnamese language selection.
- Feed enrichment/client IOC sync, Guard/Battle Mode, firewall/IP response and allow-policy management, quarantine/restore, SQLCipher/DPAPI migration, process hardening, optional BYOK AI assistance, SecConnect/licensing. These are design backlog with prerequisites in [roadmap.md](roadmap.md) and [implementation-plan.md](implementation-plan.md); no new feature implementation is authorized merely by listing it.

These items are later-version backlog only. They are not v1.0.0 controls or placeholders.

## Current UI audit

- `src/App.tsx` had Vietnamese labels, explanatory text, progress and summary text, and status names. They are now English.
- `index.html` exposed the starter template title and Vite icon; the document title is now `Zonendpoint` and the template icon reference is removed.
- `src/App.css` defines Light/Dark color tokens. The theme toggle lives on the main screen and persists the choice. No language control is present. The native picker is supplied by Windows and may follow the OS language.
- App-owned target menu, scan controls/statuses and unsigned installer now exist; apply English-only copy to these and future surfaces. Native OS-owned dialogs can follow Windows language. Historical UI notes above describe changes, not unimplemented requirements.

## Approved Quick scan/x64 update — 2026-11-07
Initial primary action is Quick scan for 13 fixed Windows core files plus the native System32/drivers subtree. Native GetSystemDirectoryW supplies the system root; this is a limited file scan, not a full-system/memory/boot integrity verdict. Chosen native File/Folder uses Scan; target menu Quick scan returns to system targets. Existing All Good/Stop/cancel/error guarantees remain. Application Windows builds/packages support x86_64 only; file contents are not filtered by architecture.

## UI simplification & Server preflight update — 2026-11-07

Approved by Zon following manual testing of 0de3208:

1. **Target Selection Menu & Quick Scan default**:
   - "Select target" menu contains "File" and "Folder" items only ("Quick Scan" is removed from the dropdown menu).
   - "Quick Scan" is the default main action button when no target is explicitly selected.
   - When a File or Folder is selected, the main button changes to "Scan".
   - After a File or Folder scan completes (any outcome, including clean, infected, error, incomplete, or user cancelled), the selected target auto-clears back to null and the primary action button returns to "Quick Scan".
   - The results of the finished scan remain visible in the result area until the next scan starts.

2. **Summary-first Result View**:
   - All files clean: single "All Good" line only; no per-file list is displayed.
   - Threats detected: lists only INFECTED files as alerts (displaying file path + threat name / signature) for subsequent handling (quarantine/remediation remains deferred to later phases). Clean files are not displayed.
   - Incomplete / Error / Cancelled: displays "Scan incomplete" (or "Scan cancelled") heading, accompanied by the mandatory warning ("Do not treat an incomplete scan as clean."), listing only non-clean files (ERROR, UNKNOWN, SKIPPED, CANCELLED). Clean files are omitted from the list.

3. **Server Preflight Verification**:
   - Before starting any scan (Quick Scan, File scan, or Folder scan), a short `zVERSION` preflight check with a fast timeout (3 seconds) is sent to the configured `ZONENDPOINT_CLAMD` daemon.
   - The response must parse as a valid ClamAV banner containing a valid signature segment (`ClamAV <version>/<signatures>/...`). This protects against offline servers and non-ClamAV services bound to the configured port.
   - If unreachable, timed out, or returning an invalid banner: the scan does not start, no files are hashed or scanned, cache is not queried or reused, no CLEAN verdict is emitted, and a single user notice is shown: `"Cannot connect to ZonEndpoint server"`. The main button immediately returns to idle.
   - When preflight succeeds, the validated engine/signature identity is reused across all files in that scan for cache validation without redundant `zVERSION` roundtrips.
   - User-facing UI copy, errors, and tooltips never expose "ClamAV", IP addresses, or port numbers.

4. **Server Connection Status Indicator**:
   - An always-visible status indicator dot is located in the top header area.
   - Green = connected ("Connected to ZonEndpoint server").
   - Red = not connected ("Cannot connect to ZonEndpoint server. Check your connection."). Clicking the red indicator initiates an immediate connectivity re-check.
   - Grey / neutral = initial check in progress ("Checking connection…").
   - Connectivity checks run at application startup, immediately before every scan as part of preflight, and periodically every 30 seconds while the application is idle. Checks are asynchronous and never block the UI.
   - A red status must never coexist with an "All Good" verdict produced by a scan started while red.
